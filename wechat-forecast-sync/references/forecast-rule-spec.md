# 微信渠道供应链预测规则

## 来源

来自钉钉文档《接收微信运营供应链部分》“开发内容 -> 预测”以及上文“常低温产品销量预测”的操作说明。

## 当前明确规则

1. 低温每周二做“本周到下周二”预测。
2. 常温待供应链通知后做“未来一个月”预测。
3. 老 BI 查询历史销量。
4. 日预测基础公式：
   - 默认看最近两个月
   - 计算日均销量
   - 若最近两个月包含大促或春节，可缩短到半个月或一周
   - 在候选结果中取最高值
5. 仓库分配：
   - 低温：京东北京仓、京东上海仓、松帆武汉低温仓
   - 常温：天泽常温济南仓
6. ERP 操作：
   - 路径：销售管理 -> 销售预测列表 -> 导入新 -> 下载模板
   - 字段：客户、编码、仓、数量
7. 大促预测：
   - 参考最近两个月及去年同类大促
   - 在选定值基础上加 5%
8. 秒杀：
   - 秒杀品数量直接加到对应日期预测
   - 数量通常 200~300
   - 周二秒杀通常周一确认

## 待补齐信息

1. 老 BI 查询接口或页面参数映射
2. 营销日历的真实来源
3. “客户”字段与渠道/仓库的映射关系
4. ERP 是否已有“销售预测修改 API”
5. 老 BI 历史销量口径：
   - 是否按支付时间
   - 是否扣除退款
   - 是否按 SKU 粒度
   - 是否区分仓库
6. 仓库分配算法：
   - 平均分配
   - 按库存能力分配
   - 按历史仓发货占比分配

## 推荐落地架构

### 第一阶段

- 输入：历史销量文件、日历文件、秒杀文件
- 输出：预测明细 JSON、ERP 导入 CSV
- 目标：先把规则和结果格式跑通

### 第二阶段

- 接老 BI 自动查询
- 接营销日历自动拉取
- 接 ERP 自动导入或更新

## 推荐输入字段

历史销量字段：

- `sku`
- `product_name`
- `date`
- `qty`

日历字段：

- `date`
- `event_type`
- `event_name`
- `scope`
- `sku`
- `adjustment`

秒杀字段：

- `date`
- `sku`
- `qty`

## 输出字段

明细 JSON：

- `date`
- `sku`
- `product_name`
- `base_qty`
- `campaign_increment`
- `flash_sale_increment`
- `final_qty`
- `warehouse_allocations`

ERP 导入 CSV：

- `客户`
- `编码`
- `仓`
- `数量`
